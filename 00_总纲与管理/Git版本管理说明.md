# Git版本管理说明

## 一、当前方案

项目根目录使用 `main` 分支管理书稿，`website` 保持为独立 Git 仓库。正文、研究卡、审读记录和合稿都使用固定文件名，不再创建带 `v+数字` 后缀的副本。

现有旧稿已经整理为以下标签：

| 标签 | 内容里程碑 |
|---|---|
| `v0.1` | 初稿、研究卡与首轮记录 |
| `v0.2` | 首轮修订与故事化试写 |
| `v0.3` | 章节扩写 |
| `v0.4` | 深度扩写 |
| `v1.0` | 写作包、审校与阶段合稿 |
| `v1.1` | 扩写合稿与统一精修 |
| `v1.2` | 深度扩写合稿 |
| `v1.3` | 突厥关系线修订 |
| `v1.4` | 第一册史实核校与精修 |
| `v1.5` | 第一册精修候选 |
| `v2.0` | 总纲重写与第三册结构重建 |

这是一条根据现存版本文件重建的“逻辑里程碑历史”，不是原始编辑时间的精确复原。第三册结构重建后曾重新从“初稿”编号开始，因此单纯按旧文件时间或数字排序都会造成误解；当前以 Git 提交关系为准。

## 二、日常使用

开始写作前查看状态：

```powershell
git status --short --branch
```

查看尚未提交的文字变化：

```powershell
git diff -- "02_第二册_贞观君臣/02_章节稿件/第14章_房谋杜断之外.md"
```

完成一章的研究卡、正文和审读后，只提交相关文件：

```powershell
git add -- "02_第二册_贞观君臣/03_研究卡/第14章_研究卡_房谋杜断之外.md"
git add -- "02_第二册_贞观君臣/02_章节稿件/第14章_房谋杜断之外.md"
git add -- "02_第二册_贞观君臣/04_审校修订/第14章_审读记录.md"
git add -- "02_第二册_贞观君臣/00_写作包与进度/第二册_写作进度表.md"
git commit -m "重写第14章：房谋杜断之外"
```

不要使用 `git add .` 把无关内容一并提交。新标签只用于全册定稿、结构重建等明确里程碑，不必每修改一段就增加标签。

## 三、比较与读取旧稿

查看一章的完整修改历史：

```powershell
git log --follow -- "01_第一册_大唐开国/02_章节稿件/第09章_新王朝的一天.md"
```

比较两个里程碑中的同一章：

```powershell
git diff v0.1..v2.0 -- "01_第一册_大唐开国/02_章节稿件/第09章_新王朝的一天.md"
```

只读取旧稿而不改动当前文件：

```powershell
git show "v0.1:01_第一册_大唐开国/02_章节稿件/第09章_新王朝的一天.md"
```

查看已经退出当前目录的第三册旧结构：

```powershell
git ls-tree -r --name-only v1.0 -- "03_第三册_武后的天下/05_旧结构素材_649-683"
```

若需要恢复旧内容，先确认工作区干净，再从旧提交复制到新文件中；不要直接回退整个仓库，以免覆盖后来章节。

## 四、提交边界

一次提交尽量对应一个可以说明清楚的写作动作，例如“完成第14章研究卡”“重写第14章正文”“统校第12—15章”。章节正文、研究卡、审读记录和进度表可以在同一章完成时合并提交，但不要把网站构建产物或其他章节的临时改动混入。

当前根仓库没有配置远程地址，只提供本地版本历史。`website` 有自己的远程地址和未提交内容，本次迁移没有修改、提交或推送它。
